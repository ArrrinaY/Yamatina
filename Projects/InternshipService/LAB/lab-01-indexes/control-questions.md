# Контрольные вопросы — Лабораторная №1

## 1. Чем EXPLAIN отличается от EXPLAIN ANALYZE?

EXPLAIN только показывает план выполнения без реального запуска запроса. EXPLAIN ANALYZE выполняет запрос и добавляет фактические метрики: actual rows, actual time, loops.

## 2. Когда Sequential Scan — нормальный план?

Когда таблица маленькая, когда запрос возвращает большую часть строк (>5–15% в зависимости от данных), или когда индекс не существует/не подходит.

## 3. Почему индекс может не использоваться?

Низкая селективность условия, устаревшая статистика (ANALYZE), функция над колонкой в WHERE (`LOWER(email)`), несовпадение типов, OR-условия, слишком большой результат.

## 4. Что такое селективность?

Доля строк, удовлетворяющих условию. Высокая селективность (мало строк) → индекс выгоден. Низкая (много строк) → Seq Scan может быть дешевле.

## 5. Чем Index Scan отличается от Index Only Scan?

Index Only Scan читает данные только из индекса (если все нужные колонки в индексе и visibility map актуален). Index Scan находит TID в индексе, затем читает heap.

## 6. Зачем Bitmap Index Scan?

Когда индекс возвращает умеренное число строк — PostgreSQL собирает TID в bitmap и читает heap блоками, снижая random I/O.

## 7. Почему важен порядок колонок в составном индексе?

B-tree индекс работает по принципу left-prefix: `(a, b)` поддерживает `WHERE a = ?` и `WHERE a = ? AND b = ?`, но не `WHERE b = ?` alone.

## 8. Что такое partial index?

Индекс только на подмножество строк (`WHERE status = 'NEW'`). Меньше размер, быстрее обновление, но работает только для запросов с тем же условием.

## 9. Что такое expression index?

Индекс по выражению (`LOWER(email)`). Нужен, когда в запросе используется функция, иначе обычный индекс по колонке не применяется.

## 10. Как индексы влияют на INSERT?

Каждый INSERT обновляет все индексы таблицы → время записи растёт пропорционально числу индексов.

## 11. Можно ли считать idx_scan = 0 доказательством бесполезности индекса?

Нет. Статистика сбрасывается, редкие но важные запросы могут не накопить scans. Удалять индекс нужно только после анализа реальных запросов.

## 12. Почему нельзя индексировать все колонки?

Рост диска, замедление записи, усложнение планировщика, многие индексы всё равно не будут использоваться.

---

## Краткая шпаргалка по типам индексов

- **B-tree** — основной, для большинства запросов.
- **Составной** — для нескольких условий сразу, порядок колонок важен.
- **Partial** — когда фильтруешь малую долю строк.
- **Expression** — когда в WHERE функция (`LOWER`, `DATE(...)`).
- **GIN** — JSON / массивы / full-text.
- **BRIN** — огромные таблицы с естественным порядком (время).
- **Индекс ≠ всегда быстрее** — при 25%+ таблицы или на маленьких таблицах Seq Scan может быть лучше.
- **Каждый индекс замедляет INSERT / UPDATE / DELETE.**
