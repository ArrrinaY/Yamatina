# Контрольные вопросы — Лабораторная №2

## 1. Почему Seq Scan не всегда является плохим планом?

На маленьких таблицах или когда запрос возвращает большую долю строк, последовательное чтение страниц дешевле множества random seek по индексу.

## 2. Почему PostgreSQL может не использовать существующий индекс?

Низкая селективность, устаревшая статистика, несоответствие выражения в WHERE индексу, OR-условия, высокая доля возвращаемых строк.

## 3. Что происходит с индексом при INSERT?

Для каждой новой строки PostgreSQL вставляет запись во все подходящие индексы — обновляет B-tree структуры.

## 4. Почему большое количество индексов может замедлять запись?

Каждый INSERT/UPDATE/DELETE должен синхронно обновить все индексы — линейный рост стоимости записи.

## 5. Что такое селективность?

Доля строк, проходящих фильтр. Высокая селективность → мало строк → индекс выгоден.

## 6. Почему индекс хорошо работает для поиска небольшой части таблицы?

Index Scan читает только нужные страницы (~N строк), а Seq Scan — всю таблицу (~M строк, M >> N).

## 7. Почему индекс может быть менее полезен, если запрос возвращает большую часть таблицы?

Стоимость чтения индекса + random heap access может превысить последовательное чтение всей таблицы.

## 8. Зачем нужен EXPLAIN ANALYZE?

Чтобы увидеть реальный план и фактическое время выполнения, а не только оценку планировщика.

## 9. Что означает Rows Removed by Filter?

Количество строк, прочитанных на этапе сканирования, но отброшенных условием Filter.

## 10. Что означает Index Cond?

Условие, которое индекс может проверить напрямую (без чтения heap).

## 11. Чем Index Scan отличается от Bitmap Index Scan?

Index Scan читает heap сразу для каждой записи. Bitmap Scan сначала собирает TID в bitmap, сортирует, затем читает heap пакетами.

## 12. Почему порядок колонок в составном индексе имеет значение?

B-tree индекс работает по left-prefix: `(a, b)` используется для `WHERE a = ?`, но не для `WHERE b = ?` без `a`.

## 13. Почему запрос с GROUP BY может оставаться дорогим даже при наличии индекса?

Индекс помогает фильтрации, но агрегация всё равно требует обработать все отфильтрованные строки и построить hash/sort групп.

## 14. Как статистика влияет на выбор плана?

Планировщик использует pg_statistics (ANALYZE). Неточная статистика → неверные estimated rows → неоптимальный план.

## 15. Что происходит с производительностью при росте таблицы?

Seq Scan растёт линейно. Index Scan для точечных запросов остаётся ~O(log N + K).

## 16. Почему нельзя создавать индексы на все колонки?

Рост диска, замедление записи, сложность обслуживания, многие индексы не используются.

## 17. Как определить размер таблицы в PostgreSQL?

```sql
SELECT pg_size_pretty(pg_relation_size('table_name'));
SELECT pg_size_pretty(pg_total_relation_size('table_name'));
```

## 18. Как определить размер индекса?

```sql
SELECT indexrelname, pg_size_pretty(pg_relation_size(indexrelid))
FROM pg_stat_user_indexes WHERE relname = 'table_name';
```
